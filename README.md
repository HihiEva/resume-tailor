# resume-tailor

使用 `initial/` 素材库与 `tmp/` 工作简历的 LaTeX 简历定制 AI skill：根据 JD 推荐经历，分层确认实习、项目及具体条目，再改写为有事实依据的量化内容，并检查一页满行排版。可按需准备求职邮件草稿及网申内容。

## 主要规则

- 默认只修改实习经历和项目经历，教育、荣誉、技能及全局模板保持原样
- 先确认所选经历及条目，局部改写无需重选整份简历
- 从真实材料中核对贡献和数字，不编造成果
- 新增或改写的条目末尾不加中文或英文句号
- 默认一页，尽量满行，以最新编译的实际 PDF 为准
- 当前 JD 只改 `tmp/`，未采用内容逐行注释保留；用户明确审核通过的新条目才注释回存 `initial/`，去重后供后续复用
- 邮件只保存草稿，文档类附件使用 PDF；网申以使用者自己的完整履历为准

## 安装到 Codex

将整个仓库放到 Codex 的 skills 目录下，文件夹名为 `resume-tailor`。默认路径是 `~/.codex/skills/resume-tailor`；自定义了 `CODEX_HOME` 时使用该目录下的 `skills/resume-tailor`。

默认配置可执行：

```bash
git clone https://github.com/HihiEva/resume-tailor.git ~/.codex/skills/resume-tailor
```

目标目录已存在时先检查已有版本，避免覆盖自己的配置。也可以下载 ZIP，解压后将包含 `SKILL.md` 的文件夹命名为 `resume-tailor`，放入上述位置。安装后重新打开会话以便发现 skill。

其他支持 `SKILL.md` 的 AI 工具可按其 skills 目录规范安装；`agents/openai.yaml` 是 Codex 的界面元数据，其他工具可忽略。

## 使用

提供当前 `.tex` 主文件、目标 JD，以及能证明本人贡献与数字的项目材料，然后调用：

```text
使用 $resume-tailor，根据这份 JD 调整我的简历
先让我选择实习、项目及其具体条目，确认后再修改
```

局部改写时可以直接指定条目；需要邮件或网申时另行说明，并提供本人的发件账号、材料目录、作品链接或完整履历。

## 简历项目目录与工作流程

skill 安装目录与简历项目是两个目录。以下路径相对于**简历项目根目录**，使用前让 AI 确认根目录；不要把材料放进已安装的 skill 目录。

```text
简历项目/
├── initial/
│   ├── resumeCh.tex      # 修改前正文与已获批的注释条目
│   ├── resumeEn.tex      # 可选英文源文件
│   ├── resume.cls        # 项目原有模板、样式及符号定义
│   ├── fonts/            # 使用者自己的字体资源
│   └── …                 # 样式、图片等模板依赖
├── tmp/
│   ├── resumeCh.tex      # 当前 JD 的独立工作文件
│   ├── resumeCh.pdf      # 本次编译结果
│   └── pdfs/             # 已有历史备份和预览，不自动视为已审核
├── output/               # 已确认的最终简历 PDF
├── 附件/                  # 本人报告、论文与作品
│   └── 量化/              # 按项目核实代码、Notebook 与研究输出
├── coverletter/          # 需要时复用已有申请信
├── 好的/                  # 可选排版参考，不取用他人成果
└── 网申内容.docx           # 可选完整履历、奖项资料
```

1. 读取 JD 和 `initial/resumeCh.tex` 的正文、全部注释，优先选择已有条目；先分层确认实习、项目及条目。
2. 需要新写或核实时，到 `附件/`、`附件/量化/` 查证事实与数字；没有对应目录或材料时说明缺失，不猜测。
3. 确认选择后在 `tmp/resumeCh.tex` 生成当前简历；同一 JD 继续修改工作文件，不从素材库覆盖最新编辑。切换 JD 前先确认现有工作是否仍需保留。
4. 在 `tmp/` 编译并检查本次生成的 PDF。模板资源可通过指向 `../initial/` 的相对链接复用，不支持链接时复制所需依赖；工作源文件不能链接到原始源文件。
5. 只有用户明确审核通过本次简历或具体条目后，才将获批的新条目逐行加 `% ` 注释，保存到 `initial/resumeCh.tex` 对应经历下。保留必要标题、日期和列表结构，不覆盖原正文、不加入取舍理由。
6. 同一经历内比对正文与注释，忽略注释前缀和排版空白；相同条目不重复添加，表述或数字不同的获批版本可以并存。后续 JD 优先复用获批条目，需要改写时重新核实。

编译成功、AI 自检通过、用户未回复均不代表审核通过。部分通过只回存对应部分；历史备份不自动入库。英文需求对称使用 `initial/resumeEn.tex` 与 `tmp/resumeEn.tex`。`output/` 的最终 PDF 按本次确认的版本使用，不自动覆盖其他版本。

## 环境与文件

仓库只包含规则和使用说明，没有执行脚本或 Python 依赖。编译与视觉检查需要使用者自己的 LaTeX 环境、项目字体、模板依赖及 PDF 预览能力。没有编译或预览工具时，skill 会说明未验证的部分。

本仓库不附带简历模板、个人简历、证书或报告。请自行提供 `.tex` 及其引用的 `.cls`、`.sty`、图片等文件；邮件和网页操作还需要使用者环境中可用并已授权的对应工具。

```text
resume-tailor/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── README.md
```

这是可分享的通用版本，学校、邮箱、单位、项目、奖项及作品链接均由当前使用者提供；目录按上述相对路径约定，可由使用者明确指定其他位置。
